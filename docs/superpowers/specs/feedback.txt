### 一、 两个代码实现上的“小 Bug / 边界漏洞”微调

#### 1. `realtime_signal_widget` 中的分位数计算逻辑

* **当前代码**：


```python
# 源码片段[cite: 3]
percentile = updated['ratio'].iloc[-1] / updated['ratio'].rolling(750).max().iloc[-1]

```


* **隐患**：这里误写成了 `比值 / 最大值`（这只是比值占最大值的比例），而不是滚动百分位数（Percentile Rank）。


* **修正建议**：复用你在 `strategy.py` 中写好的向量化函数：


```python
# 修正后：直接取最后一行计算好的 percentile[cite: 3]
percentiles = calculate_rolling_percentile(updated['ratio'], window=750)
percentile = percentiles.iloc[-1]

```



#### 2. 中证红利实时接口代码匹配

* **当前代码**：


```python
# 历史数据用的 H20922（中证红利全收益）[cite: 3]
# 但实时报价处传的是 sh000922（中证红利价格指数）[cite: 3]
hl_price = get_realtime_quote('sh000922') 

```


* **隐患**：实时计算比值时，盘中的实时红利价格指数（`000922`）和历史全收益指数（`H20922`）点位存在跨越式的绝对基数差距，直接相除会导致盘中比值瞬间畸变。


* **修正建议**：
* **方案 A**：实时报价也调取全收益代码 `shH20922`（若接口支持）。


* **方案 B（推荐）**：盘中实时计算比值时，使用**涨跌幅进行增量更新**。即：



$$\text{Today Ratio} = \text{Yesterday Close Ratio} \times \frac{1 + \text{创业板实时涨跌幅}}{1 + \text{红利价格指数实时涨跌幅}}$$



这样可以完美避开价格指数与全收益指数点位不一致的问题！
